# PoC 근거표

기획서(지원서 1~6번)가 내세우는 주장마다 실제로 되는지, 근거가 무엇인지 적는다.
기능을 확인할 때마다 이 표의 상태와 근거를 고친다. 확인하지 못한 건 추측하지 않고 "미확인"으로 둔다.

상태: ✅ 확인됨 · ❌ 미확인 · ⚠️ 기획서와 다름(기획서 수정 필요)

## 기술 동작

| 기획서 주장 | 지원서 | 기능 | 상태 | 근거 |
|---|---|---|---|---|
| 정차 중엔 화면, 주행 중엔 음성으로 자동 전환 | 3, 5-1 | F1 | ✅ | 기어 D에서 UXR 켜짐, DO 선언 앱은 70km/h에서도 화면 유지. 앱에서 기어 P↔D에 따라 MenuScreen↔DrivingScreen 전환 확인(11/11) (`docs/sdk_check.md`) |
| 주행 중 음성으로 주문 (STT) | 3, 5-2 | F2 | ✅ | 앱에서 시연 대사 3개를 녹음 파일로 넣어 3개 모두 정확히 인식, 중간 결과는 자막으로 표시 (11/11, `docs/sdk_check.md` F2) |
| 음성으로 안내 (TTS) | 5-2 | F4 | ✅ | 초기화·onReady·onStart 확인. 재생 완료 `onDone`은 에뮬레이터에서 오지 않음 → 끝나는 시점은 글자 수로 계산 (11/11) |
| 고른 지점을 내비 경유지로 자동 추가 | 3, 5-2 | F8 | ✅ | 앱 S1 흐름에서 주문 완료 뒤 고른 지점(길목사거리 정차구역)을 `addWaypoint`로 넣음. 내비 화면에 경유지 표시, 목적지 서현역 유지. 추가 전후 5,100m·1,020초 → 5,100m·1,020초로 미리 잰 값(+0분)과 일치 (11/11, `F8_waypoint_1111.png`) |
| 경유지 추가로 늘어난 거리·시간을 잴 수 있음 | 6-1 | F8 | ✅ | `getDestinationInfo` 전후 차이: +1.2km, +5분 (`docs/sdk_check.md`) |
| 후보 지점마다 추가 시간을 앱이 계산 | 5-1, 5-2 | F7 | ✅ | 후보마다 `requestRouteWithWaypoints`로 경로를 새로 요청하면 실제 내비 값이 나옴(후보 5곳 +2~10분, 약 12초씩). `requestTrip`은 현재 위치→후보만 줌. 시연에선 미리 측정한 값 사용 (`docs/sdk_check.md` 0단계) |
| 경로 근처 가게만 추천 | 3, 5-1 | F6 | ✅ | FusedLocation 실제 차 위치를 OSRM 경로에 내려, 앞쪽 500m 안 가게만 지나가는 순서로 추천. 출발점: 길목김밥(앞 1,999m)·모퉁이김밥(앞 3,612m), 길목김밥을 지난 위치: 모퉁이김밥만(앞 1,108m). 지나친 시흥김밥·1km 떨어진 먼길김밥은 빠짐 (11/11) |

| 창문 열고 닫으면 수령 감지 | 5-1, 5-2 | F13 | ✅ | 앱 S1 흐름에서 수령 지점 도착 뒤 운전석 창문 열림(10)→닫힘(0)을 받아 "음식 받으셨나요?" → "응 받았어" → 수령 완료, 경유지를 빼고 원래 경로(서현역 5.1km)로 복귀 (11/11, `F13_route_back_1111.png`, S1 스모크 2회 연속 통과) |

## 성과 지표 (6-1)

| 기획서 주장 | 측정 방법 | 상태 | 근거 |
|---|---|---|---|
| 경로 위 수령 시 원래 경로에서 평균 0.5km 이내 이탈 | 같은 출발·도착에서 '가게 들러 포장'과 '경로 위 수령'의 추가 거리 비교 (F7·F8) | ✅ | 시흥동→서현역(5.1km) 내비 실측: 앱이 고른 수령 지점 +0m, 후보 5곳 평균 +380m, 가게 들러 포장 +600m (11/11, `F7_pickup_measure_1111.json`) |
| 가게 들러 포장(+15분) 대비 경로 위 수령(+3분) | 같은 비교의 추가 시간. 영상 콘티의 +15분·+3분은 자리표시 | ⚠️ | 내비 실측은 포장 +2분(+600m) vs 수령 +0분. **+15분·+3분과 맞지 않는다.** 포장의 주차·하차·걷기 시간은 내비로 재지 않아 빠져 있다. 영상·기획서 숫자를 실측으로 바꾸거나 포장 쪽 추가 시간을 따로 재야 한다 |
| 주행 중 화면 터치 0회로 주문 완료 | S1 흐름을 끝까지 돌려 터치 카운터 확인 (F1·F5) | ✅ | 기어 D에서 대사 3개로 가게 제안 → 9,500원 확인 → 주문 완료, 화면 터치 0회 (11/11, `scripts/smoke_s1.sh`). 수령 지점·경유지는 F7·F8에서 이어 붙임 |
| 위치 입력 단계 3단계 → 0단계 | 배민에서 주차장 주소로 결제 직전까지 진행해 캡처, 본 앱과 비교 | ❌ | 수동 확인 |
| 하차 0회 | S1·S2 시연에서 확인 | ✅ | S1: 창문으로 받고 수령 완료(차 문 열림 이벤트 없음). S2: 기사가 차 옆까지 와서 전달하는 흐름. 실제 사람의 하차 여부는 시연 영상으로 보여줄 부분 (11/11) |

## 기록 규칙

- 측정 원본(계산 로그 JSON, logcat, 캡처)은 이 폴더에 `F7_pickup_log_1112.json`처럼 기능 ID와 날짜를 붙여 둔다.
- 영상과 기획서에 쓰는 숫자는 여기 있는 원본에서만 가져온다.
